# Privacy

**PcHealthCheck has no telemetry, no crash reporting, and no phone-home. Ever.**

- **Every health check works fully offline.** No check in this app contains network code — the CI build fails if any assembly other than `PcHealth.Net.Optional` so much as mentions `System.Net`. A scan makes zero connections, and the receipt after every scan says so.
- Scan results exist only in memory until **you** export them, via a save dialog, to a location you choose (HTML or JSON). Nothing is uploaded anywhere.
- The "What you can do" section is built only from readings already in this report. It reads nothing of its own, and its sentences never quote a reading's detail line.
- The app never reads the contents of your documents, photos, or personal files. Startup-item checks read program binaries only (to verify signatures and compute hashes).
- The System overview check lists the **five programs holding the most memory and the five that used the most processor time**, by program name only, for example "brave ×29 5.5 GB". It never includes paths, window titles or command lines. Like the startup program names, these appear in the report and travel with it if you share it.
- The app never modifies your system. The only file it writes during a scan is a temporary battery report inside its own folder, which is deleted after parsing — and shown in the post-scan receipt.
- Administrator rights are requested only if you select an admin check, and only for a separate short-lived helper process that exits when the scan ends. The main window never runs elevated. The helper reads drive health, restore points and shadow copies, platform security settings, and what starts up for the other accounts on this PC — it never reads your files, and never reads BitLocker recovery keys or product keys into a report. The main window tells the helper which Windows account started the scan, by the ID Windows gives the account (its SID), because the helper runs as whoever typed the administrator password. That ID is not written into the report.
- **One exception to "never modifies your system":** the "Temperatures & fans" check loads a kernel-level driver, because CPU and motherboard sensors cannot be read any other way. It is opt-in, carries its own **LOADS DRIVER** badge, and the elevated helper asks you about it separately in its own dialog — declining just leaves temperatures out of the report. The driver is used to read sensor values only; the app never sets fan speeds, clock rates, or voltages.
- **Optional tool installs are consented twice and reversible.** If a reading needs an extra tool, the app shows the exact command before running it (plus the UAC prompt), and records that *it* installed the tool. When you close the app it offers to remove what it installed — after checking the tool wasn't already on your PC and that no running program is using it — and logs the removal with the reinstall command in `dependency-history.txt` (kept 15 days). The app never removes anything it did not install.
- **There is exactly one feature that uses the internet: the VirusTotal second opinion**, and it never runs by itself. It needs your own free API key, typed in each time — the app never stores it and none is built in. Before anything is sent, a dialog lists every fingerprint that would leave the machine, in full. What is sent is a SHA-256 fingerprint per file and nothing else: **your files are never uploaded**, so their contents stay here. A fingerprint does tell VirusTotal that this PC holds a file with those exact bytes, which is why the list is short, capped, and shown to you first. The receipt then reports how many lookups were actually made, counted by the app rather than promised.
- **On-demand malware scans** (the "Quick scan" and "Scan a folder" buttons) ask Windows Defender to do the work; the app makes no connection of its own. Defender's own cloud protection may contact Microsoft during a scan, exactly as it would for a scan you started from Windows Security — the consent dialog says so before you agree. A folder scan runs with remediation switched off, so Defender reports what it finds and moves nothing; a quick scan lets Defender act on what it finds using your normal settings.
- Consent choices are stored locally in `%APPDATA%\PcHealthCheck\consent.json`. Delete it anytime to reset every choice to OFF.
- Cards you hide with **Don't show again** in the window are remembered in `%APPDATA%\PcHealthCheck\dismissed-advice.json`. For each card it keeps a 16-character one-way fingerprint of what the card says is wrong, and the day you hid it — no drive name, drive letter, number or reading. A card comes back by itself when it gets worse. **Show again** deletes the file, and so can you. Exported reports and the JSON list every card, and the headless console prints the first five and how many more the report holds; none of them hides a card. Only the normal, unelevated window reads or writes this file: a window started with "Run as administrator" hides nothing, and the headless scan, the administrator helper and the laptop audit kit never touch it.
- Trend history is stored locally in `%LOCALAPPDATA%\PcHealthCheck\history.db`. It holds only measurement names, the drive or volume they belong to, and numbers — enough to notice that a failure counter is growing, and nothing else. It never leaves the machine. Switch it off with the checkbox on the main screen (or `--no-history`), erase it with the **Delete history** button, or simply delete the file. Every scan tells you in the receipt exactly how many measurements it recorded.
- **The laptop audit kit** (`1 - Check this laptop.cmd`, for checking company laptops before handover) reads more than the app itself:
  - the laptop's **serial number**, to name its result file, plus its BIOS version, memory slots and disk types;
  - the laptop's **hardware UUID**, a fixed ID its firmware reports, so that two laptops with no serial are still told apart;
  - a short fingerprint of the name of each result already on the stick, so the summary can tell which check came last without trusting the laptops' clocks (a fingerprint, so a zip holds no other laptop's serial or name);
  - your answers to its questions about the laptop's physical condition;
  - the computer name and the name of the Windows account the kit runs under, which Windows PowerShell writes at the top of the kit's own log (`audit-transcript.txt`) on every kit version.

  Everything stays on your USB stick, in one zip per laptop (plus a folder beside it if the kit's window was closed early), and the kit lists the zip's contents before you send it anywhere. The app itself never reports a serial number. To link its drive readings, it reads Windows' device path for each disk, which for some USB disks contains the disk's serial, but that path is used only in memory: a drive it cannot match is named by a short one-way fingerprint, never by the path (PRIV-003). During a kit run the app keeps its temporary files (the battery report) on the stick, not on the laptop, so the app writes none of its files to the laptop's disk even if the kit's window is closed half-way. As a safety net, the kit also removes the app's own folder from the laptop if the run created one. Only if the stick cannot be written does the kit save the result to the laptop's Desktop instead, and it says so on screen.
- **Windows 11 readiness** is read from the verdict Windows keeps in its registry (the same compatibility check Windows Update uses). Nothing is sent anywhere to get it.
- **Windows support and updates** are read from Windows itself, offline: Windows Update is asked only about its local cache, never to search online, and nothing is sent anywhere.
  - The edition (for example Pro or Home) and the running build with its update number, such as 19045.6466, from the registry.
  - On Windows 10, whether Microsoft's Extended Security Updates licence is active: the licence state of the ESU add-on rows, matched by Microsoft's published IDs. The report says whether a key is installed; the key itself is never read into it.
  - Which cumulative update the running build came from (its KB number, from Windows' servicing records), and that update's release date from Windows Update's local cache.
  - Whether Windows Update is set to use a company update server (WSUS or Configuration Manager), from its policy in the registry. Only that switch is read, never the server's name: on such a PC the cached date is the server's approval date, so the update's age is not graded.
  - How many updates are waiting, counted by type (security and quality, drivers, firmware), and the date Windows Update last searched.
- **Startup programs:**
  - For each item, the publisher its signature names, for example "Kilonova LLC". It is read offline, from the file itself or, for Windows' own files, from the signature catalogs Windows keeps on the PC. Nothing is sent anywhere.
  - Task Manager's on/off switch for each item, so an item you switched off is left out.
  - A startup file's location is written with a folder token, such as `%LOCALAPPDATA%\Programs\...`, never with your user folder. So is every path in a non-default Winlogon Shell or Userinit value.
  - The admin check of other accounts numbers them ("Account 2") in the order Windows created them, and lists each item by its name only. It never looks up an account's name. It opens each account's profile folder only to list its Startup folder, and reads a Run entry's command only to skip an empty one, never writing it. The report says which number is yours when the scan was started from the normal window; when the app itself was started with "Run as administrator", which may be another person's account, it says only which account started the scan.
- **Drives and how they are connected:**
  - Which disk each drive letter is on, whether each disk is plugged in over USB (or another external connection) or is inside the PC, and whether it is an SSD or a hard disk. Read from Windows without administrator rights. A USB drive's free space, encryption and disk errors are shown, but not counted toward this PC's health.
  - The report also lists, per disk, whether it is the system disk, inside the PC or external, and the total space in use on its lettered drives. A disk is named by its drive letters ("C:, D:"), or by its number when it has none, never by a drive's label.
  - Drive-health rows in the JSON report carry Windows' number for the drive (0, 1, 2 and so on), never its serial.
  - Before the disk benchmark writes its test file, it reads the disk errors in the System event log and the other checks' findings from the same scan, so it never writes to a drive the scan calls failing.
- **When Windows was installed** (the install date Windows keeps), read when no quick scan has ever run, Reliability Monitor's history is empty, or Defender has caught nothing in the last 90 days. The System overview also reads it on every scan, and uses it only to tell whether the Windows 11 verdict Windows keeps is older than this Windows (a restored disk image brings the verdict of the PC it was made on). On an install under a week old the first two are not judged, and the report says how many days ago Windows was installed, never the date itself.
- **How far back Windows' records go,** so that a "last 90 days" count says how many days it really covers: the date of the oldest entry in the System and Application event logs and in Reliability Monitor's history, and how many days Defender keeps its detection history (its own setting). The report gives the number of days, never a date.
- **File backup** is read without administrator rights, for the account the app runs as: whether File History has settings for it (the folder is checked, its files are not opened), the File History service's start mode, whether Desktop, Documents and Pictures point into a OneDrive folder, and the folder of each OneDrive account signed in for it, to tell whether OneDrive really backs them up. The report says yes or no, and names those three folders; it never writes their paths or the OneDrive account's folder. Only restore points and shadow copies need the administrator helper.
- **Linux checks (in development, not in any release yet).**
  - They read only files under `/proc`, `/sys` and `/etc/os-release`. They run no program, write no file and need no root.
  - The battery's serial number is never read.
  - Network filesystems (NFS, SMB, SSHFS) are never asked for their free space, because asking would make a connection.
  - The report lists your disks by mount point, which can include your user name (for example `/media/<you>/<drive>`), and the computer's maker and model, never its serial number.
- Verify us: run a scan with Wireshark or GlassWire open — you will see zero connections from this app. (Start a VirusTotal lookup and you will see exactly the connections that dialog told you about, and no others.) The receipt panel after each scan lists every process spawned, every file written, and every lookup made.
